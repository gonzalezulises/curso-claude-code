# 9.1 · El modo sin conversación — solución de referencia

## Lo más simple que ya sirve

```bash
cat error.log | claude -p "¿Qué causó este fallo? Sé breve."
```

Sin abrir sesión. Es la puerta de entrada natural, y hace evidente el salto
siguiente: si funciona a mano, funciona igual dentro de un script.

## Un script real

```bash
#!/usr/bin/env bash
set -euo pipefail

# Resumen diario de los commits de ayer.
DESDE=$(date -v-1d +%Y-%m-%d 2>/dev/null || date -d yesterday +%Y-%m-%d)

git log --since="$DESDE" --pretty=format:'%h %s' \
  | claude -p "Resume estos commits en 5 líneas para el equipo.
               Agrupa por área. No inventes nada que no esté en la lista." \
  > resumen-$DESDE.md

echo "escrito resumen-$DESDE.md"
```

**Por qué empezar por algo así:** no decide nada, no toca código, y te enseña el
mecanismo completo con riesgo cero. Desde ahí, el salto a algo que sí decide
—bloquear un merge, abrir una incidencia— es pequeño y llegas con la
infraestructura probada.

## Salida estructurada

```bash
claude -p "¿Este diff introduce algún fallo? Responde SOLO JSON:
           {\"bloqueante\": true|false, \"motivo\": \"...\"}" \
  --output-format json
```

Eso convierte al agente en algo que otro programa consume: un paso más de una
tubería, no un final. Es la diferencia entre «me escribe un resumen que leo yo» y
«me devuelve un veredicto que decide si el pipeline sigue».

## Los tres fallos que aquí no se corrigen solos

1. **La tarea se queda a medias y termina igual.** Sin condición de aceptación
   escrita, el agente decide él cuándo terminó — y decide pronto.
2. **Se queda esperando.** Si algo pide confirmación, no hay nadie. Los permisos
   tienen que estar resueltos **antes**.
3. **Cuesta más de lo previsto.** Pon un límite de tiempo o de intentos.

Los tres se resuelven escribiendo el encargo completo antes de lanzarlo, en vez
de irlo aclarando sobre la marcha.

## Sobre el coste

Empieza por lo programado —una vez al día— antes que por cada evento. El cron te
deja ver el gasto real antes de multiplicarlo por el número de pull requests.
